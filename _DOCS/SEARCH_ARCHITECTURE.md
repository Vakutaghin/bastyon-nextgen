# Архитектура поиска в старом приложении

## Обзор

Старое приложение Pocketnet/Bastyon использует ограниченную систему поиска, которая позволяет искать посты по ключевым словам в рамках ленты профиля пользователя. Поиск выполняется через RPC метод `getprofilefeed` с параметром `keyword`.

---

## 1. Технологический стек

### RPC API для поиска

**Основной метод:** `getprofilefeed`

**Прокси-серверы:**
- `1.pocketnet.app:8899` - `6.pocketnet.app:8899` (Production)
- `test.pocketnet.app:8899` (Testnet)

**Протокол:**
- HTTPS на порту 8899 для RPC запросов
- Эндпоинт: `/rpc/getprofilefeed`

### Кеширование

- Результаты поиска кешируются в `storage['shares']`
- Ключ кеша формируется из параметров запроса
- Используется для быстрого доступа и оптимизации повторных запросов

---

## 2. Функциональность поиска

### Поиск постов

**Единственный способ поиска в старом приложении** - это поиск постов конкретного пользователя через параметр `keyword` в методе `getprofilefeed`.

**Ограничения:**
- ❌ Нет глобального поиска по всем постам
- ❌ Нет поиска пользователей по имени или адресу
- ❌ Нет поиска по тегам (только фильтрация)
- ✅ Только поиск постов в ленте конкретного пользователя

### Что можно искать

**Поля поиска:**
- `m` (message) - полный текст поста
- `c` (caption) - заголовок/капшн поста

**Что НЕ ищется:**
- Теги постов (`t`)
- Имена пользователей
- Адреса пользователей
- Комментарии к постам
- Метаданные видео/аудио

## 3. RPC метод getprofilefeed

### Параметры запроса

```typescript
{
  method: 'getprofilefeed',
  parameters: [
    0,              // height - высота блока (0 = последние)
    '',             // txid - ID транзакции для пагинации ('' = с начала)
    10,             // count - количество постов
    'ru',           // lang - язык контента
    [],             // tagsfilter - фильтр по тегам
    [],             // type - тип контента
    [],             // пустой параметр
    [],             // пустой параметр
    [],             // tagsexcluded - исключенные теги
    'PJT8eTrx...',  // address - адрес пользователя
    'новости',      // keyword - ключевое слово для поиска ⭐
    'time',         // orderby - поле для сортировки
    'desc'          // ascdesc - направление сортировки (asc/desc)
  ],
  options: { auth: false } // Не требует авторизации
}
```

### Параметр keyword

| Параметр | Тип | Описание | Пример |
|----------|-----|----------|--------|
| **keyword** | string | Ключевое слово для поиска в тексте постов | `'новости'`, `'технологии'` |

**Особенности:**
- Поиск выполняется в полях `m` (message) и `c` (caption) поста
- Поиск чувствителен к регистру (точное совпадение)
- Пустая строка `''` означает отсутствие поиска (возвращаются все посты)
- Поиск работает только в рамках постов конкретного пользователя (параметр `address`)

### Пример использования

```javascript
// В старом приложении
psdk.node.shares.hierarchical(
  {
    count: 20,
    lang: 'ru',
    height: 0,
    tagsfilter: [],
    tagsexcluded: [],
    type: [],
    txid: '',
    address: 'PJT8eTrxXD5uCFL2QmRmdDJtCBA1R68Tdf',
    keyword: 'новости',  // Поиск по ключевому слову
    orderby: 'time',
    ascdesc: 'desc'
  },
  callback,
  cache,
  { method: 'getprofilefeed' }
)
```

## 4. Структура ответа

### GetProfileFeedResponse

```typescript
{
  result: 'success' | 'error',
  data: {
    height: number,              // Высота блока блокчейна
    contents: Array<Post | UserProfile>  // Массив постов или профилей
  },
  node?: string,                 // IP:PORT узла
  time: {                        // Метрики времени выполнения
    preparing: number,
    cache: number,
    start: number,
    ready: number,
    node?: {
      rpcsstart?: number,
      rpcsend?: number
    }
  },
  error?: string
}
```

### Структура поста в результатах поиска

```typescript
{
  hash: string,           // Хеш поста
```

## 5. Особенности реализации

### Кеширование результатов

**Механизм:**
- Результаты поиска кешируются в `storage['shares']`
- Ключ кеша формируется из всех параметров запроса, включая `keyword`
- Разные поисковые запросы создают разные записи в кеше

**Пример ключа кеша:**
```javascript
// Ключ формируется из параметров
const cacheKey = JSON.stringify({
  method: 'getprofilefeed',
  address: 'PJT8eTrx...',
  keyword: 'новости',
  count: 20,
  lang: 'ru',
  // ... другие параметры
})
```

### Пагинация результатов поиска

**Механизм:**
- Используется параметр `txid` для пагинации
- Для первой страницы: `txid = ''`
- Для следующей страницы: `txid = последний_пост.txid`

**Пример:**
```javascript
// Первая страница
const firstPage = await getProfileFeed({
  txid: '',
  keyword: 'новости',
  // ...
})

// Вторая страница
const secondPage = await getProfileFeed({
  txid: firstPage.data.contents[firstPage.data.contents.length - 1].txid,
  keyword: 'новости',
  // ...
})
```

### Сортировка результатов

**Параметры сортировки:**
- `orderby`: поле для сортировки (`'time'`, `'scoreSum'`)
- `ascdesc`: направление (`'asc'` или `'desc'`)

**Доступные поля:**
- `time` - по времени создания
- `scoreSum` - по сумме оценок (популярность)

### Фильтрация в сочетании с поиском

Поиск можно комбинировать с фильтрами:

```javascript
{
  keyword: 'новости',           // Поиск по ключевому слову
  lang: 'ru',                   // Только русский язык
  tagsfilter: ['политика'],     // Только посты с тегом "политика"
  type: ['post'],               // Только текстовые посты
  tagsexcluded: ['спам']        // Исключить посты с тегом "спам"
}
```

## 6. Ограничения и недостатки

### Ограничения поиска

1. **Нет глобального поиска:**
   - Нельзя искать по всем постам в сети
   - Поиск работает только в рамках профиля конкретного пользователя

2. **Нет поиска пользователей:**
   - Нет RPC метода для поиска пользователей по имени
   - Нет поиска пользователей по адресу
   - Нет автодополнения имен пользователей

3. **Ограниченный поиск по контенту:**
   - Поиск только в тексте поста (`m` и `c`)
   - Не ищется в тегах, комментариях, метаданных

4. **Простой алгоритм поиска:**
   - Вероятно, используется простое текстовое совпадение
   - Нет полнотекстового поиска
   - Нет морфологии (поиск по словоформам)
   - Нет ранжирования по релевантности

5. **Нет истории поиска:**
   - В старом приложении нет встроенной истории поисковых запросов
   - Пользователь должен помнить свои запросы

### Что отсутствует

- ❌ Глобальный поиск по всем постам
- ❌ Поиск пользователей
- ❌ Поиск по тегам (только фильтрация)
- ❌ Поиск в комментариях
- ❌ Автодополнение поисковых запросов
- ❌ Поисковые подсказки
- ❌ Сохраненные поисковые запросы
- ❌ Расширенный поиск (AND, OR, NOT)
- ❌ Поиск по дате
- ❌ Поиск по типу контента в сочетании с текстом

## 7. Использование в старом приложении

### Вызов поиска

**Метод:** `psdk.node.shares.hierarchical()`

**Файл:** `pocketnet.gui/js/satolist.js`

```javascript
// Поиск постов пользователя
psdk.node.shares.hierarchical(
  {
    count: 20,
    lang: '',
    height: 0,
    tagsfilter: [],
    tagsexcluded: [],
    type: [],
    txid: '',
    address: userAddress,
    keyword: searchQuery,  // Поисковый запрос
    orderby: 'time',
    ascdesc: 'desc'
  },
  function(result) {
    // Обработка результатов
    if (result && result.data && result.data.contents) {
      // Отображение найденных постов
      displayPosts(result.data.contents)
    }
  },
  cache,  // Кеш для результатов
  { method: 'getprofilefeed' }
)
```

### Обработка результатов

**Смешанный контент:**
- Массив `contents` может содержать как посты, так и профили пользователей
- Необходимо проверять тип элемента перед обработкой

```javascript
result.data.contents.forEach(item => {
  if ('type' in item) {
    // Это пост
    console.log('Пост:', item.c, item.m)
  } else {
    // Это профиль пользователя
    console.log('Пользователь:', item.name)
  }
})
```

## 9. Сравнение с другими методами

### getprofilefeed vs gethierarchicalstrip

| Параметр | gethierarchicalstrip | getprofilefeed |
|----------|----------------------|----------------|
| **Поиск** | ❌ Нет | ✅ Есть (keyword) |
| **Назначение** | Иерархическая лента | Лента профиля + поиск |
| **Фильтрация** | По подпискам/времени | По адресу пользователя |
| **Сортировка** | По времени | Настраиваемая (orderby, ascdesc) |
| **contents** | Только посты | Посты + профили |

### getprofilefeed vs gettopfeed

| Параметр | gettopfeed | getprofilefeed |
|----------|------------|----------------|
| **Поиск** | ❌ Нет | ✅ Есть (keyword) |
| **Назначение** | Топ-лента по популярности | Лента профиля + поиск |
| **Ранжирование** | По рейтингу (scoreSum) | Настраиваемая сортировка |
| **Глобальность** | Все посты в сети | Только посты пользователя |

## 10. Примеры использования

### Поиск постов пользователя

```javascript
// Найти посты пользователя, содержащие слово "новости"
const searchResults = await getByPRC({
  method: 'getprofilefeed',
  parameters: [
    0,                    // height
    '',                   // txid (первая страница)
    20,                   // count
    'ru',                 // lang
    [],                   // tagsfilter
    [],                   // type
    [],                   // пустой
    [],                   // пустой
    [],                   // tagsexcluded
    'PJT8eTrx...',        // address пользователя
    'новости',            // keyword - поисковый запрос
    'time',               // orderby
    'desc'                // ascdesc
  ],
  options: { auth: false }
})

// Обработать результаты
searchResults.data.contents.forEach(post => {
  if (post.type) {
    console.log('Найден пост:', post.c)
    console.log('Текст:', post.m)
  }
})
```

### Поиск с фильтрами

```javascript
// Найти видео-посты пользователя на русском языке, содержащие "технологии"
const videoSearch = await getByPRC({
  method: 'getprofilefeed',
  parameters: [
    0,
    '',
    20,
    'ru',                 // Только русский язык
    [],                   // tagsfilter
    ['video'],            // Только видео
    [],
    [],
    [],
    'PJT8eTrx...',
    'технологии',         // Поисковый запрос
    'scoreSum',           // Сортировка по популярности
    'desc'
  ]
})
```

### Пагинация результатов поиска

```javascript
async function searchAllPosts(userAddress, keyword) {
  let allResults = []
  let txid = ''
  let hasMore = true

  while (hasMore) {
    const page = await getByPRC({
      method: 'getprofilefeed',
      parameters: [
        0,
        txid,
        50,                // Больше постов на страницу
        '',
        [],
        [],
        [],
        [],
        [],
        userAddress,
        keyword,
        'time',
        'desc'
      ]
    })

    if (page.data.contents.length > 0) {
      allResults = allResults.concat(page.data.contents)
      txid = page.data.contents[page.data.contents.length - 1].txid
      hasMore = page.data.contents.length === 50
    } else {
      hasMore = false
    }
  }

  return allResults
}
```

## 11. Метрики и производительность

### Время выполнения

**Структура метрик:**
```typescript
{
  preparing: number,    // Время подготовки запроса (мс)
  cache: number,       // Время работы с кешем (мс)
  start: number,       // Время начала обработки (мс)
  ready: number,       // Время готовности ответа (мс)
  node?: {
    rpcsstart?: number,  // Время начала RPC запроса (мс)
    rpcsend?: number     // Время отправки RPC ответа (мс)
  }
}
```

### Оптимизация

1. **Кеширование:**
   - Результаты поиска кешируются для быстрого доступа
   - Разные запросы создают разные записи в кеше

2. **Пагинация:**
   - Используйте разумный размер страницы (10-50 постов)
   - Загружайте следующую страницу только при необходимости

3. **Фильтрация:**
   - Применяйте фильтры на стороне сервера для уменьшения объема данных

**Ограничения:**
- ❌ Нет глобального поиска по всем постам
- ❌ Нет поиска пользователей
- ❌ Ограниченный поиск только в тексте постов
- ❌ Простой алгоритм поиска без морфологии

**Рекомендации:**
- Создать отдельные RPC методы для глобального поиска и поиска пользователей
