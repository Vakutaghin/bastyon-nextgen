## Поток данных при воспроизведении

```
1. Пользователь кликает на видео
   │
   ▼
2. Post Component находит элемент [data-plyr-provider="peertube"]
   │
   ▼
3. Вызов PlyrEx(target, options, callback)
   │
   ▼
4. Динамическая загрузка video-embed.bundle.js
   │
   ▼
5. PeerTubeEmbeding.main(target, videoId, host, options)
   │
   ├─► Получение информации о видео (GET /api/v1/videos/{id})
   │
   ├─► Загрузка манифеста (GET /master.m3u8)
   │
   ├─► Парсинг плейлиста качества
   │
   ├─► Инициализация P2P Manager (если useP2P = true)
   │   │
   │   ├─► Подключение к трекерам
   │   ├─► Поиск пиров
   │   └─► Обмен картами сегментов
   │
   └─► Создание HTML5 video элемента
       │
       ▼
6. Загрузка сегментов
   │
   ├─► P2P путь (приоритет):
   │   ├─► Поиск сегмента у пиров
   │   ├─► Загрузка через WebRTC
   │   └─► Сохранение в IndexedDB
   │
   └─► HTTP путь (fallback):
       ├─► Загрузка с сервера
       └─► Сохранение в IndexedDB
       │
       ▼
7. Воспроизведение
   │
   ├─► Сегменты подаются в video элемент
   ├─► Адаптивный битрейт (ABR)
   ├─► Обновление прогресса
   └─► Сохранение истории просмотра
```

## P2P архитектура

```
                    ┌──────────────┐
                    │   Tracker    │
                    │   Servers    │
                    └──────┬───────┘
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
        ▼                  ▼                  ▼
   ┌─────────┐       ┌─────────┐       ┌─────────┐
   │ Peer A  │◄─────►│ Peer B  │◄─────►│ Peer C  │
   │         │       │         │       │         │
   │ Seg: 1,2│       │ Seg: 3,4 │       │ Seg: 5,6 │
   └────┬────┘       └────┬────┘       └────┬────┘
        │                 │                  │
        └─────────────────┼──────────────────┘
                          │
                          ▼
                   ┌──────────────┐
                   │   Client     │
                   │  (You)       │
                   │              │
                   │  Загружает:  │
                   │  - Seg 1,2   │
                   │    от Peer A │
                   │  - Seg 3,4   │
                   │    от Peer B │
                   │  - Seg 5,6   │
                   │    от Peer C │
                   └──────────────┘
```

## Структура хранения в IndexedDB

```
IndexedDB: "assets"
├── ObjectStore: "assets"
│   └── Key: [requestUri, requestRange, masterSwarmId]
│       └── Value: { requestUri, requestRange, masterSwarmId, data }
│
├── ObjectStore: "segments"
│   └── Key: [id, masterSwarmId]
│       └── Value: { id, masterSwarmId, sequence, range, lastAccessed, ... }
│       └── Index: masterSwarmId (для быстрого поиска)
│
└── ObjectStore: "segmentsData"
    └── Key: [id, masterSwarmId]
        └── Value: { id, masterSwarmId, data: ArrayBuffer }
```

## Жизненный цикл сегмента

```
1. Запрос сегмента
   │
   ├─► Проверка Memory Cache
   │   └─► Найден? → Использовать
   │
   ├─► Проверка IndexedDB
   │   └─► Найден? → Загрузить в Memory Cache → Использовать
   │
   └─► Не найден? → Загрузка
       │
       ├─► P2P: Поиск у пиров → WebRTC загрузка
       │
       └─► HTTP: Загрузка с сервера
           │
           ▼
2. Сохранение
   │
   ├─► Memory Cache (быстрый доступ)
   │
   └─► IndexedDB (долгосрочное хранение)
       │
       ▼
3. Использование
   │
   └─► Подача в video элемент
       │
       ▼
4. Очистка (LRU)
   │
   ├─► По времени (5 мин для cache, 60 мин для IndexedDB)
   │
   └─► По количеству (45 для cache, 300 для IndexedDB)
```
