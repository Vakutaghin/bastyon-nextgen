# Android: APK подписан постоянным ключом

Раньше CI подписывал APK отладочным ключом, а он у каждой сборки свой. Поэтому новая версия на Android не вставала поверх старой: приложение приходилось удалять вместе с ключами аккаунтов. К тому же такой APK был debuggable, и его данные читались через adb без root.

Теперь релиз собирает релизный APK и подписывает его постоянным ключом. Изменения в main, коммит `c94e3bd`. Ключ я создал сам и храню у себя. Через API со своего аккаунта dukvanduken я добавил в репозиторий два секрета, их видно в Settings -> Secrets and variables -> Actions:

- `ANDROID_KEYSTORE_B64`
- `ANDROID_KEYSTORE_PASSWORD`

## Что важно

1. Не удаляй и не меняй эти два секрета. С другим ключом APK снова не встанет поверх установленного. Без ключа сборка Android в релизе упадет, и APK в релизе не будет.
2. Скрипт `scripts/android-signing-key.sh` запускать не нужно: ключ уже создан. Второй ключ сломал бы обновления, и скрипт его создать не даст.
3. Если сборка Android в релизе упадет с ошибкой про ключ подписи, напиши мне. Я верну секреты из резервной копии.

## Отпечаток сертификата SHA-256

```
15a6c4d71540be9f66a1f5456f3615f78fd6dc7ad4643fcd8fe4fa2c896c2bcc
```

Как проверить, что APK наш:

```
apksigner verify --print-certs <файл.apk>
```

Строка "SHA-256 digest" должна совпасть с отпечатком.

## Первый релиз с этим ключом

Первым так подписан 0.8.0 (29.09.2026). Тем, у кого стоит 0.7.1 или более ранняя версия, пришлось удалить приложение в последний раз: поверх старой подписи новая версия не встанет. Перед удалением нужно было проверить, что фраза восстановления записана. Начиная с 0.8.0 обновления ставятся поверх, без удаления.
