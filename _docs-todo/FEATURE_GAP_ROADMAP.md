# Roadmap: остаток работ (паритет с pocketnet.gui)

> Что ещё не хватает в **bastyon-nextgen** по сравнению с легаси **pocketnet.gui**
> (`/private/var/www/pocketnet/___original-repos/pocketnet.gui`).
>
> Документ — карта **остатка работ**: только несделанное, сгруппированное по
> приоритетам. Сделанное здесь не перечисляется. Детальные таблицы по доменам
> (только незакрытые строки) — в конце.

**Легенда статусов:** 🟡 частично/заглушка · ❌ нет · 🔌 UI есть, не подключено к RPC

**Принцип** (см. память `principle_decentralization`): мнемоника-only, без SSO/посредников,
работа standalone. Поэтому ряд легаси-фич (email/SSO, node-control, FCM-пуши, electron-обвязка,
Olm/Megolm, cordova-камера/контакты, P2P-видео) — **намеренно вне скоупа** и здесь не перечисляются.

> верифицировать, что он ещё актуален. Ряд реализованного **не верифицирован на живой
> ноде** (нет стенда) — это отдельный пласт проверки, не покрытый этим документом.

## Q-PLAN: приоритеты

### 🔴 P0 — разрывы базовых сценариев (остаток)

1. 🟡 **Редактирование профиля — осталось:** **обложка** (отдельный `accSet`-tx,
   write-кода нет) и крипто-адреса.
2. 🟡 **История транзакций кошелька — осталось:** история по доп. Z-адресам
   отдельным списком. *(Метки boost/stake — сделаны; метка «Чаевые» — 2026-09-29:
   сообщение перевода, а с ним `a:donate`, теперь пишется в OP_RETURN, как у
   старого клиента, и история читает его оттуда.)*
3. 🟡 **Загрузка видео на PeerTube — осталось:** видео-кабинет (`videoCabinet`,
   `pages/my-videos-page` — заглушка), обложка и описание при загрузке, импорт по URL.
   *Загрузка своего видео или аудио из композера сделана 2026-09-27.*
4. ❌ **YouTube в десктопе не играет.** В прод-сборке Tauri встроенный плеер
   показывает «Ошибка настройки видеопроигрывателя. Ошибка 153» и ссылку «Посмотреть
   видео на YouTube» (macOS, 0.6.0, 2026-09-27). Код эмбеда с 0.5.0 не менялся, так
   что сломано и там. Вероятная причина: YouTube требует от встроенного плеера
   заголовок Referer, а iframe со страницы `tauri://localhost` его не отправляет.
   Проверить Windows (`http://tauri.localhost`) и Android. Origin приложения менять
   нельзя: к нему привязаны localStorage и IndexedDB пользователей.
   🟡 2026-09-29: на страницах не-http(s) (`tauri://`, macOS и Linux) вместо плеера
   превью ролика с кнопкой «Смотреть на YouTube» — открывает браузер
   (`canEmbedYoutube`, `video-embed-url.ts`). Windows и Android по-прежнему встраивают
   iframe — там всё ещё нужна проверка на живой сборке.

## Незакрытое из аудита 2026-09

Аудит (`APP_AUDIT_2026-09.md`, удалён 2026-09-25 — `git show efe6cf3:_docs-todo/APP_AUDIT_2026-09.md`)
закрыт кодом целиком, кроме пунктов ниже: им нужна координация с legacy, отдельный дизайн
или доступ к деплою. Ручные проверки на живых сборках — в `MANUAL_CHECKS.md`.

**Протоколы и хранение секретов** — отдельные задачи с миграцией, не «между делом»:
- **S72.** Групповые сообщения шифруются AES-CBC с фиксированным IV
  (`messenger/services/encryption-service.ts`) под долгоживущим ключом комнаты — homeserver
  видит повторы. Формат общий с legacy `bastyon-chat`, поэтому новая версия формата
  (случайный IV) — только синхронно с ним.
- **VP-12.** Записи сейфа (мнемоники, список аккаунтов) — `crypto-js` AES-CBC без
  аутентификации под секретом сейфа (сам секрет уже в AES-GCM). Перевести записи на AES-GCM с
  версией формата: двойное чтение, запись в новом, e2e на реальном IndexedDB.
- **Р6.** Кэш расшифрованной переписки (`decryptedMessages`) при выходе и удалении аккаунта
  чистится, при смене аккаунта остаётся — в открытом виде. Шифровать ключом из сейфа.
- **Р1, вариант A.** Под Tor медиа и эмбеды сейчас не грузятся сами (вариант B: CSP + загрузка
  по клику). Проксировать webview Tauri через SOCKS Tor (`proxy_url`) — исследование: окно
  придётся пересоздавать после старта Tor, поддержка на macOS/Linux ограничена.

**Кошелёк:** трата с Z-адресов (P2SH-вход с redeemScript). Сейчас приём на них скрыт, баланс
виден (решение Р2).

**Деплой:** заголовок `frame-ancestors 'self'` для всего, кроме `/embed/*` — в meta браузер эту
директиву игнорирует; в клиенте есть только страховка (S67: вне `/embed/*` во фрейме
приложение не рендерится).

**Гигиена, по желанию:**
- 224 предупреждения eslint и ~1334 ошибки vue-tsc (в основном типизация пропсов
  styled-компонентов) — рост держит гейт «не больше baseline».
- e2e (`pnpm test:e2e`, 22 теста, ходят в живые ноды) — не в CI.
- Разрезать `use-comment-form.ts` и `post-card-comments.vue`, общий примитив «оптимистичное
  сообщение» для комментариев и мессенджера — польза только для кода, а проверить форму
  ответа можно лишь с аккаунтом. Без живого прогона не браться.

## IPFS: остаток

Модуль сделан: Kubo по требованию (с отменой установки и GC кэша), окно просмотра, публикация,
приватные ссылки, удалённый pin, сохранение с публичного шлюза с проверкой по CID
(`src-tauri/src/ipfs/verify.rs`), а в вебе и на телефоне — открытие ссылок с той же проверкой
(`src/helpers/ipfs/ipfs-verify.ts`). Дизайн-док закрыт 2026-09-26; решения и список «проверено
аудитом, не перепроверять» — `git show 1fd9f53:_docs-todo/IPFS_VIEWER_MODULE_DESIGN.md`. Ручные
проверки — в `MANUAL_CHECKS.md`, разделы «IPFS в десктопе» и «IPFS в браузере и на телефоне».
Файлообменник («Мои файлы», отправка через чат, большие файлы) сделан 2026-09-26, план закрыт:
`git show 46cc5ae:_docs-todo/IPFS_FILE_SHARING_PLAN.md`. Не сделано сознательно:

**Файлообменник**
- Папки. Опубликовать можно (`ipfs add -r`), а скачать с проверкой — нет: `verify.rs` и
  `ipfs-verify.ts` собирают один файл. Нужны обход каталога и сохранение дерева (на десктопе
  в папку, в браузере — архивом).
- Перетаскивание файлов. Нативный drag-and-drop Tauri выключен (`dragDropEnabled: false`),
  иначе на Windows ломается перетаскивание во вложения чата. HTML5 отдаёт содержимое, но не
  путь, а публикация байтов из webview позволила бы XSS публиковать что угодно с IP
  пользователя. Путь: байты в Rust, публикация — после нативного подтверждения.
- Прогресс публикации: сейчас «Публикую…» без процентов; нужен построчный разбор
  `ipfs add --progress --enc=json`.

**Безопасность**
- Показ через публичный шлюз по CID не проверяется (сохранение проверяется). Окно просмотра
  изолировано: без IPC, `incognito`, навигация по белому списку, в заголовке назван шлюз.
  Проверенный показ одиночного файла: собрать его тем же `verify.rs` во временный файл и
  открыть через asset-протокол Tauri. Для сайтов (каталог с `index.html` и относительными
  ресурсами) нужен свой проверяющий прокси (custom protocol) — отдельная задача.
- IPNS и DNSLink через публичный шлюз сохраняются без проверки. DNSLink не подписан; запись
  IPNS подписана, но проверка подписи (ed25519 + CBOR) не сделана.
- Секреты в argv (аудит D3): bearer `--api-auth` на каждом вызове CLI и токен pin-сервиса при
  настройке видны в `ps`, пока идёт команда. Уйти можно, вызывая RPC Kubo напрямую (reqwest с
  `Authorization`) вместо CLI. На однопользовательском компьютере риска нет.
- CSP главного окна широкая (аудит D13, не IPFS): `'unsafe-inline' 'unsafe-eval'`,
  `connect-src https://* http://*`. Это задача по CSP всего приложения.

**Функции**
- Просмотр зашифрованных медиа в окне. Сейчас приватная ссылка только сохраняется на диск.
- PDF на Linux: WebKitGTK его не показывает, сейчас сохранение. Нужен pdf.js во вьювере.
- Subdomain-шлюз для изоляции недоверенных сайтов. Сейчас все IPFS-сайты на одном origin
  `127.0.0.1:<порт>`, изоляция — `incognito` в каждом окне.
- Свой шлюз вместо `dweb.link` (Kubo на своём VPS) — решено не делать: нагрузка и
  злоупотребления легли бы на свой сервер. `dweb.link` остаётся Tier 0.

## Найдено при написании справки (2026-09-28/29)

Справку я сверял с кодом, нодой и прежним клиентом; что можно было исправить сразу, исправлено
отдельными коммитами `fix(...)`. Ниже — то, что осталось: для этого нужны решение, дизайн или
проверка на живом устройстве.

**Лента и посты**
- Нет выбора периода и сортировки для «Сначала лучшее».
- У изменённого поста нет пометки «изменено».
- Монеты, приложенные к комментарию (заработок type 204), нигде не показаны: они влияют только
  на сортировку.
- Метка «Проверен» почти не появляется: бейджи ноды не выводятся, список `self.real` прежнего
  клиента не перенесён.
- Субтитры видео включаются сами, выключателя нет.

**Профиль и модерация**
- Кнопка жалобы видна всем, хотя сеть принимает жалобы только от опытных аккаунтов.
- Блокировка из профиля без подтверждения.
- «Начать чат» есть и в своём профиле.
- Поле почты при регистрации ни на что не влияет.

**Мессенджер**
- Перевод из прежнего Bastyon (`bastyon://i?stx=…`) показывается ссылкой, а не карточкой:
  сумму надо брать из транзакции.
- Перевод собеседнику без опубликованных ключей уходит, а сообщение о нём — нет (повтор не
  поможет). Проверять ключи до транзакции.
- Звук нового сообщения не подчиняется переключателю «Звук» в уведомлениях.
- Подсказка про свайпы при записи голосового видна и тем, кто пользуется мышью.

**Сеть**
- Свою ноду для всего приложения не выбрать; живая, но отставшая нода не перевыбирается
  (перевыбор только по ошибке транспорта).

**Приложение**
- Закрытие окна завершает приложение: раздавать файлы IPFS в фоне без окна нельзя.
- Мини-приложение после «Закрыть» уводит в ленту, а не обратно в каталог.
- Android: APK подписан отладочным ключом (обновление только с удалением), push-уведомлений нет.

**Проверить вживую**
- YouTube на Windows и Android (iframe вместо превью), запись голосовых и камера для QR на
  Windows и Linux.

**Мусор**
- `getBestMimeType` больше не используется; ключ `explorerShared.copyUrlFromAddressBar` — тоже.
