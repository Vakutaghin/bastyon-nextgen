# Файлообменник на IPFS — план

Цель: делиться файлами любого размера со всеми пользователями Bastyon, в ленте и в чате,
без своего сервера хранения. Основа уже есть в десктопе: «Поделиться файлом», «Поделиться
приватно», удалённый pin, открытие и проверенное сохранение ссылок (остаток модуля IPFS —
в `FEATURE_GAP_ROADMAP.md`, раздел «IPFS: остаток»).

## Модель: P2P, как торрент (решено 2026-09-26)

- Файл раздаёт тот, у кого он есть: сначала отправитель, потом те, кто скачал и оставил его
  на раздаче. Пока никого из них нет в сети, файл недоступен — шлюз отвечает 504, и
  пользователь видит «тот, кто поделился, сейчас не в сети».
- Круглосуточно — только через сторонний pinning-сервис со своим токеном («Удалённый pin»).
  Своего сервиса хранения нет: место, трафик и жалобы на чужие файлы легли бы на мой сервер,
  по той же причине нет и своего шлюза.
- Раздаёт только десктоп: у веба и телефона нет ноды, они получают через публичный шлюз.
- Раздающего видно по IP любому, кто знает ссылку. Под Tor IPFS выключен целиком.

## Этапы

### 1. Открытие в вебе и на телефоне — сделано 2026-09-26

- Показ — новая вкладка с `dweb.link` (как окно просмотра на десктопе). Скачивание — CAR с
  `trustless-gateway.link` с проверкой каждого блока по CID: `src/helpers/ipfs/ipfs-verify.ts`,
  близнец `verify.rs`, тесты на тех же фикстурах. `dweb.link` для CAR не годится: его редирект
  на trustless-шлюз без CORS.
- Шлюз отдаёт блоки в порядке обхода с повторами (`order=dfs, dups=y`) — файл идёт потоком,
  память не растёт с размером. Без этого порядка блоки копятся в буфере до 256 МБ.
- «Показать или скачать»: по расширению — сразу в обработчике клика; без него — по первым
  проверенным байтам, и тогда вкладку открывает кнопка «Открыть» (жест клика уже истёк).
  Показываю только типы, которые все браузеры отображают сами: иначе браузер скачал бы файл
  со шлюза мимо проверки (CSV в Chrome, Markdown в Firefox, HEIC).
- Сохранение: Chrome и Edge — диалог и запись на диск; Firefox и Safari — Blob до 1 ГБ;
  телефон — кэш приложения и системное «Поделиться».
- Приватный файл собирается в памяти целиком (до 512 МБ) и расшифровывается WebCrypto.
- Библиотеки IPLD грузятся отдельным чанком только при скачивании.

### 2. «Мои файлы»

- Реестр опубликованного: имя, размер, дата, CID, ссылка, публичный или приватный, ключ
  приватного, статус удалённого pin. Хранит Rust в данных приложения с правами 0600 — там
  ключи. Чей реестр, ноды или аккаунта, решу в начале этапа: в приложении несколько аккаунтов,
  и ключи файлов одного не должны быть видны другому.
- Раздел «Файлы» вместо двух кнопок в меню шапки: список, «Скопировать ссылку», «Перестать
  раздавать» (unpin у себя и на сервисе, дальше GC), статус копии на сервисе («копируется /
  сохранено / ошибка», `ipfs pin remote ls`) — видно, когда можно выключить компьютер.
- Публикация с именем: `ipfs add -w`, ссылка `ipfs://<каталог>/<имя>`. Получатель сразу
  видит имя и тип, и решение «показать или скачать» не ждёт первых байт.
- Перетаскивание файлов в раздел.

### 3. Отправка через чат

- Во вложениях — «Через IPFS»: для файлов больше лимита чата (25 МБ) и по выбору. В чате —
  карточка файла (имя, размер, «Скачать»), в тексте сообщения — ссылка для старых клиентов.
- Приватный файл: ключ едет в сообщении; в зашифрованном чате его видят только участники.
- Получатель на десктопе может оставить скачанное на раздаче (pin у себя) — так файл живёт,
  пока в сети хоть кто-то из получивших.

### 4. Большие файлы

- Приватные — формат v2: шифрование кусками (AEAD на каждый кусок, как в age/STREAM) без
  чтения файла в память, в Rust и в браузере. Ссылки v1 открываются как раньше.
- Прогресс и отмена публикации и сохранения на десктопе (в браузере уже есть).
- Несколько файлов и папки за раз (`ipfs add -r`), скачивание папки.
