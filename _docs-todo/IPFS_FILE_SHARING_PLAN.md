# Файлообменник на IPFS — план

Цель: делиться файлами любого размера со всеми пользователями Bastyon, в ленте и в чате,
без своего сервера хранения. Основа уже есть в десктопе: «Поделиться файлом», «Поделиться
приватно», удалённый pin, открытие и проверенное сохранение ссылок (остаток модуля IPFS —
в `FEATURE_GAP_ROADMAP.md`, раздел «IPFS: остаток»).

## Модель: P2P, как торрент (решено 2026-09-26)

- Файл раздаёт тот, у кого он есть: сначала отправитель, потом те, кто скачал и оставил его
  на раздаче. Пока никого из них нет в сети, файл недоступен — шлюз отвечает 504, и
  пользователь видит «тот, кто поделился, сейчас не в сети».
- Круглосуточно — только через сторонний pinning-сервис со своим токеном («Удалённый pin»).
  Своего сервиса хранения нет: место, трафик и жалобы на чужие файлы легли бы на мой сервер,
  по той же причине нет и своего шлюза.
- Раздаёт только десктоп: у веба и телефона нет ноды, они получают через публичный шлюз.
- Раздающего видно по IP любому, кто знает ссылку. Под Tor IPFS выключен целиком.

## Этапы

### 1. Открытие в вебе и на телефоне — сделано 2026-09-26

- Показ — новая вкладка с `dweb.link` (как окно просмотра на десктопе). Скачивание — CAR с
  `trustless-gateway.link` с проверкой каждого блока по CID: `src/helpers/ipfs/ipfs-verify.ts`,
  близнец `verify.rs`, тесты на тех же фикстурах. `dweb.link` для CAR не годится: его редирект
  на trustless-шлюз без CORS.
- Шлюз отдаёт блоки в порядке обхода с повторами (`order=dfs, dups=y`) — файл идёт потоком,
  память не растёт с размером. Без этого порядка блоки копятся в буфере до 256 МБ.
- «Показать или скачать»: по расширению — сразу в обработчике клика; без него — по первым
  проверенным байтам, и тогда вкладку открывает кнопка «Открыть» (жест клика уже истёк).
  Показываю только типы, которые все браузеры отображают сами: иначе браузер скачал бы файл
  со шлюза мимо проверки (CSV в Chrome, Markdown в Firefox, HEIC).
- Сохранение: Chrome и Edge — диалог и запись на диск; Firefox и Safari — Blob до 1 ГБ;
  телефон — кэш приложения и системное «Поделиться».
- Приватный файл собирается в памяти целиком (до 512 МБ) и расшифровывается WebCrypto.
- Библиотеки IPLD грузятся отдельным чанком только при скачивании.

### 2. «Мои файлы» — сделано 2026-09-26

- Страница `/my-files` (только десктоп, со входом в аккаунт): «Поделиться файлом», «Поделиться
  приватно», список опубликованного, «Скопировать ссылку», «Перестать раздавать». Вход — из
  меню аккаунта и из меню IPFS в шапке; кнопки публикации и удалённого pin переехали туда.
- Реестр ведёт Rust (`src-tauri/src/ipfs/shares.rs`): `app_data_dir/ipfs/shares/<адрес>.json`,
  права 0600, запись через временный файл. Реестр — у аккаунта: нода одна на устройство, а
  ключи приватных файлов одного аккаунта не видны другому. Нечитаемый реестр откладывается
  в `.bad`, а не перезаписывается.
- Публичный файл публикуется в каталоге-обёртке (`ipfs add -w`), ссылка
  `ipfs://<каталог>/<имя>`: получатель видит имя и тип сразу. Приватный — без обёртки, иначе
  имя стало бы публичным.
- «Перестать раздавать»: pin снимается у себя и на сервисе (со всеми статусами, не только
  готовые копии) и сразу GC. Если тот же CID раздаёт другой аккаунт устройства, pin остаётся.
  Без демона GC идёт под `start_lock`, а `run_ipfs` повторяет команду при занятом `repo.lock`.
- Статус ноды на странице («раздаются, пока открыт Bastyon» / «сейчас не раздаются») и копий
  на сервисе (`pin remote ls`, пачками по 10 CID; пока копируется — опрос раз в 15 с).
- Удаление аккаунта с устройства снимает с раздачи его файлы; удаление модуля IPFS стирает
  реестры вместе с repo.

### 3. Отправка через чат — сделано 2026-09-26

- В меню вложений чата (десктоп) — «Файл через IPFS». Приватно по умолчанию: ключ едет в
  самом сообщении, в зашифрованном чате его видят только участники. Больше 512 МБ приватно
  пока нельзя — предлагаю отправить по ссылке.
- Сообщение — обычный текст со ссылкой (имя, ключ и размер во фрагменте), поэтому старые
  клиенты видят ссылку. Наш рисует карточку: имя, размер, «Открыть» или «Скачать» — тот же
  путь, что клик по ссылке (десктоп — Rust, веб и телефон — проверенное скачивание). В списке
  диалогов вместо ссылки — «📎 имя файла».
- «Раздавать дальше» на чужой карточке (десктоп): файл закрепляется у получателя
  (`ipfs pin add`), попадает в его «Мои файлы» с пометкой «получен, раздаю».
- Выбор файла отделён от публикации: `ipfs_pick_file` отдаёт токен, имя и размер (путь
  остаётся в Rust), `ipfs_publish` публикует по токену. Так размер известен до публикации.
- Файл больше лимита чата (25 МБ, картинка — 100 МБ) раньше молча не отправлялся, теперь —
  предупреждение и подсказка про IPFS.

### 4. Большие файлы

- Приватные — формат v2: шифрование кусками (AEAD на каждый кусок, как в age/STREAM) без
  чтения файла в память, в Rust и в браузере. Ссылки v1 открываются как раньше.
- Прогресс и отмена публикации и сохранения на десктопе (в браузере уже есть).
- Несколько файлов и папки за раз (`ipfs add -r`), скачивание папки.
- Перетаскивание файлов на страницу «Мои файлы». Путь из webview Rust не принимает (иначе XSS
  публиковал бы любой файл), поэтому брошенные файлы ловит сам Rust по событию окна
  `DragDrop`, а фронт лишь подтверждает публикацию.
