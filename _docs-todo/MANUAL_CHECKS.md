Что код и тесты уже покрывают, но что проверяется только вживую: нужен аккаунт с балансом,
сборка под платформу или второй клиент. Собрано из аудита 2026-09 при его закрытии

- [ ] Вход по мнемонике: поле скрыто, «глаз» работает. Вход по WIF (ключ на `5`/`6`/`2`) пускает в тот же аккаунт, что и мнемоника.
- [ ] Регистрация: отмена поверх живой сессии возвращает к ней; перезагрузка посреди регистрации — сид показан после подтверждения; «Обновить капчу» даёт картинку, а не пустое поле.

Если сеть всё же отвергла имя после капчи — модалка открывается снова с причиной словами, повтор с другим именем идёт без капчи и без новых монет; после перезапуска та же модалка и пункт «Завершить регистрацию» в меню аватара. `iplimit` — текст про лимит по IP, а не код.
- [ ] Смена аккаунта A→B: подписки, чёрный список, уведомления, избранное и `/limits` — от B; WS-пуши приходят по B.
- [ ] Публикация: пост появляется без F5; при медленной ноде нет дубля (одна транзакция); правка видео-поста сохраняет видео, видимость и язык; удаление убирает пост из ленты.
- [ ] Комментарии: ответ на ответ виден в ветке; счётчик «Осталось N символов» склоняется.
- [ ] Оценки: отредактированный пост оценивается; свой пост оценить нельзя; 1★ показывается как низкая оценка.
- [ ] Уведомления приходят до первого открытия выпадашки и переживают перезапуск; бейдж гаснет после закрытия; тумблеры типов влияют на список.
- [ ] «Сначала лучшее» с окнами сутки / 3 дня / неделя; обрыв сети на догрузке ленты — посты остаются, под ними ошибка и «Повторить».
- [ ] Кошелёк: перевод обновляет баланс и показывает реальную комиссию; bitcoin-адрес отвергается понятным текстом; история не зависит от ноды, закреплённой в эксплорере.
- [ ] Чёрный список убирает автора из ленты, бустов и рекомендаций и глушит переписку.
- [ ] Профиль: смена имени на «a/b» или со словом «bastyon» отвергается; сохранение «О себе» со старым именем проходит.
- [ ] Настройки → Система: тумблер автозапуска совпадает с системой после выключения автозапуска в настройках ОС.

## Опросы в постах

Сделаны 28.09.2026. Нода не хранит поле опроса `p`, поэтому опрос лежит в `s.poll`, а голос — комментарий к посту с номером варианта в `info` (`helpers/content/poll.ts`). Проверено в браузере без публикации: лента с подменённым ответом ноды показывает опрос и итоги, голоса не видны в обсуждении и не входят в число комментариев; вход тест-мнемоником, голос и публикация поста с опросом — с перехваченной отправкой транзакции (`s.poll` в payload на месте). В сети ни одного опроса и голоса не публиковалось.

- [ ] Опубликовать пост с опросом с настоящего аккаунта: в ленте у другого аккаунта опрос виден, `getrawtransactionwithmessagebyid` отдаёт `s.poll`.
- [ ] Проголосовать: отметка «ждёт подтверждения», через блок-два голос приходит с ноды, отметка снимается, итоги не удваиваются. Голосовать второй раз нельзя.
- [ ] Голос в старом приложении (bastyon.com): комментарий «🗳 вариант», сам опрос не виден.
- [ ] Правка поста с опросом: опроса в окне нет, после сохранения он на месте и голоса те же.

## Mesh-радио: Meshtastic (десктоп, нужны 2 платы с прошивкой 2.5+)

Протокол прогнан против настоящей прошивки: два `meshtasticd` 2.7.26 в Docker, связанные UDP
multicast, — рукопожатие, канал, ЛС с PKI и ACK от получателя, ответ, приватный канал по
ссылке, admin. Интерфейс — против поддельного радио (`src/mesh/meshtastic/testing`, e2e
`mesh.spec.ts`). Живых плат не было.

Прогон против `meshtasticd` (раз в релиз прошивки):

```bash
docker network create bst-mesh
for n in 1 2; do docker run -d --name bst-mt$n --network bst-mesh --restart unless-stopped \
  -p 127.0.0.1:4403$n:4403 meshtastic/meshtasticd:2.7.26-alpine \
  meshtasticd -d /tmp/mt -h 02:11:22:33:44:0$n; done
# Регион RU и UDP multicast (Config.network.enabled_protocols = 1) — один раз, любым клиентом,
# узлы после этого перезапускаются. Флаг -s не использовать: с ним прошивка выключает PKI,
# а генератор случайных чисел одинаков у всех узлов (одинаковые ключи).
MESHTASTICD=127.0.0.1:44031,127.0.0.1:44032 npx vitest run meshtasticd.live
```

Узлы отвечают на обмен NodeInfo не раньше 10 минут после старта и одному просящему — раз в
12 часов, поэтому live-тест передаёт ключ через `add_contact`, как клиенты делают на практике.

- [ ] USB на macOS, Windows и Linux: платы на CP2102, CH340, ESP32-S3 и nRF52 (родной USB — данные только при DTR). «Подключить» → «Подключено», узел, узлы сети и каналы на месте. Отключение не перезагружает плату (HUPCL снят), накопленные сообщения после повторного подключения приходят.
- [ ] Bluetooth: поиск находит радио по сервису Meshtastic; сопряжение с PIN (на экране или 123456); чтение fromRadio по уведомлениям, рукопожатие с сотней узлов проходит за разумное время.
- [ ] Wi-Fi: ESP32 по адресу в локальной сети, порт 4403. Второй клиент (официальное приложение) выбивает Bastyon — понятная ошибка, а не цикл переподключений.
- [ ] Новое радио без региона: предупреждение, выбор «Россия (868 МГц)» → радио перезагружается, «Подключено» без действий; смена пресета и имени — то же.
- [ ] Две платы: ЛС туда и обратно с «✓✓» (ключи узлов, PKI); собеседник без ключа — «Запросить ключ» или ошибка no_key с понятным текстом; выключенный собеседник — «Не отправлено» после повторов радио.
- [ ] Ответ и реакция из Bastyon видны в официальном приложении Meshtastic, и наоборот.
- [ ] Основной канал LongFast: «✓✓ услышали и передали дальше» при наличии соседа. Приватный канал: «Ссылка» → открыть её в официальном приложении на второй плате → переписка идёт; «Добавить по ссылке» — ссылкой из официального приложения.
- [ ] Длинное кириллическое сообщение: части с паузой 2,5 с, все доходят (прошивка режет чаще 2 с).
