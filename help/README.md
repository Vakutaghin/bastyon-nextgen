# Справка Bastyon: как устроена и как её вести

Справка — обычные Markdown-файлы в этой папке. На GitHub и в редакторе их читают как есть, а приложение при сборке берёт эти же файлы и показывает в разделе «Справка» (`/help`) — с оглавлением, указателем, поиском и избранным, как в справках CHM. Второй копии нет: что лежит здесь, то и в приложении, той же версии.

Читать справку: [по-русски](ru/README.md), [in English](en/README.md).

## Где что лежит

```
help/
  README.md          этот файл: правила
  ru/                основной язык
    README.md        главная справки: заголовок, вступление, оглавление
    glossary.md      словарь
    <статья>.md      одна тема — один файл
  en/                перевод: те же файлы, та же структура
  images/            картинки и схемы для обоих языков
```

- Имя файла — адрес статьи: `ru/faq.md` открывается как `/help/faq` и `bastyon://help/faq`. Только латиница, цифры и дефисы. Переименование ломает ссылки на статью, поэтому без нужды не переименовываю.
- Оглавление — первый маркированный список в `README.md` языка после подзаголовка. Пункт — ссылка на статью, вложенный список — её подразделы; статья с подразделами становится «книгой». Каждая статья в оглавлении ровно один раз.
- Иерархия есть только в оглавлении, а статьи лежат в одной папке: перенос статьи в другую книгу не меняет её адрес.

## Статья

```md
---
keywords: [IPFS, большие файлы, приватная ссылка]
platforms: [desktop]
code: [src/pages/my-files-page, src-tauri/src/ipfs]
---

# Заголовок

Вводный абзац: одна-две фразы о том, что в статье. Он же — подпись в поиске и на главной.

## Раздел

…
```

Шапка необязательна:

- `keywords` — слова для вкладки «Указатель». Заголовок статьи попадает туда сам.
- `platforms` — где работает то, что описано: `desktop`, `web`, `mobile`. Статья получает плашку «Где работает».
- `code` — файлы и папки, которые описывает статья. По ним `pnpm help:stale` находит статьи, которые могли устареть.

`platforms` и `code` пишу только в русской статье — английская берёт их оттуда.

## Разметка

Только то, что GitHub показывает сам, — поэтому файл одинаково выглядит и там, и в приложении.

- **Статья**: `[текст](faq.md)`, её раздел — `[текст](faq.md#как-войти)`, раздел этой же статьи — `[текст](#как-войти)`. Якорь — заголовок раздела по правилам GitHub: строчными буквами, без знаков препинания, пробелы — дефисы.
- **Термин** — ссылка на раздел словаря: `[блокчейне](glossary.md#блокчейн)`. В приложении это всплывающее определение, на GitHub — переход в словарь. Раздел словаря — заголовок второго уровня и текст под ним.
- **Раздел приложения**: `[«Мои файлы»](bastyon://my-files)`. В приложении открывает раздел, на GitHub остаётся текстом. Годятся разделы из `DEEP_LINK_SECTIONS` (`src/helpers/common/deep-link.ts`).
- **Название кнопки или раздела интерфейса** — жирным в кавычках: `**«Кошелёк»**`, по-английски `**“Wallet”**`. Тест сверяет его с надписями интерфейса: если кнопку переименуют, тест назовёт статью.
- **Врезки GitHub**: `> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`, `> [!CAUTION]` — маркер своей строкой, текст ниже.
- **Подробности для любопытных** — сворачиваемый блок. Пустые строки после `</summary>` и перед `</details>` обязательны:

  ```md
  <details>
  <summary>Как это устроено</summary>

  Внутри — обычная разметка.

  </details>
  ```

- **Картинки** — только свои, из `help/images`: `![Схема](../images/p2p.svg)`. Вариант для тёмной темы — вторая картинка с `#gh-dark-mode-only`, у светлой тогда `#gh-light-mode-only`, как на GitHub. Чужие картинки не показываются: загрузка выдала бы чужому серверу, кто читает справку.
- Таблицы, списки, код и цитаты — как обычно. Остальной HTML не поддерживается, комментарии `<!-- -->` можно.

## Как писать

- Сначала понятным языком — что это и зачем, потом как устроено. Технические подробности — в `<details>`.
- К читателю на «вы», названия — как в интерфейсе.
- Русская версия основная, английская — её перевод: те же файлы, то же оглавление.

## Как справка остаётся актуальной

- Меняю поведение приложения — в том же коммите правлю статьи, которые его описывают. `pnpm help:stale` показывает статьи, чей код из `code:` менялся позже них.
- Тест `src/helpers/help/help-content.test.ts` идёт вместе с остальными и проверяет:
  - оглавление и файлы совпадают, у русской и английской справки одна структура;
  - ссылки, якоря, термины и картинки существуют;
  - `bastyon://` ведёт в разделы приложения, а не в профиль с похожим именем;
  - названия кнопок в кавычках есть в интерфейсе;
  - пути из `code:` существуют;
  - контекстная справка в коде ведёт на существующие статьи.

## Контекстная справка

- Кнопка «?» рядом со сложным местом: `<HelpLink topic="how-to-buy-pkoin" />`, с подписью — `:label="…"`. Статья открывается в боковой панели, экран остаётся на месте.
- F1 открывает статью про текущий экран — её имя в `meta.helpTopic` маршрута (`src/router/index.ts`). Если статьи нет, открывается главная справки.
- Из кода — `useHelpStore().openTopic('faq')`.

## Как это устроено в приложении

- Файлы попадают в сборку через `import.meta.glob` (`src/helpers/help/help-files-*.ts`) отдельным чанком на язык и грузятся при первом открытии справки.
- Разбор — markdown-it (`src/helpers/help/help-markdown.ts`), вывод — свои компоненты (`src/b-components/help/`), без `v-html`.
- Поиск — MiniSearch с учётом окончаний (`help-stem.ts`, `help-search.ts`).
- Раздел — `src/pages/help-page/`, боковая панель — `src/b-components/help/help-panel.vue`.
