# Обслуживание ноды

Как обновлять ноду, правильно её останавливать, следить, что она в строю, и не потерять монеты.

## Обновление

Новые версии выходят на [странице релизов pocketnet.core](https://github.com/pocketnetteam/pocketnet.core/releases), Docker-образы — с тегами по номеру версии на Docker Hub; образ иногда появляется на час-два раньше релиза. Обязательные обновления — те, что меняют правила сети с определённого блока, — нужно поставить до этого блока, иначе нода выпадет из сети, см. [Правила сети и обновления](blockchain-rules.md).

**Пакет .deb:**

```
pocketcoin-cli stop
sudo dpkg -i pocketnetcore_<версия>_linux_x64_setup.deb
```

Дождитесь, пока нода остановится (процесс `pocketcoind` пропадёт из `ps`), и только потом ставьте пакет. Затем запустите ноду так же, как обычно.

**Docker Compose:**

```
docker compose pull
docker compose up -d
```

В `docker-compose.yml` версию лучше указывать явно (`pocketnetteam/pocketnet.core:0.22.21`, а не `latest`): так видно, что стоит, и обновление происходит, только когда вы меняете номер.

После обновления:

- проверьте версию — `pocketcoin-cli getnodeinfo`;
- разблокируйте кошелёк, если он зашифрован, иначе стейкинг стоит, см. [Стейкинг на своей ноде](node-staking.md);
- убедитесь, что высота растёт.

## Правильная остановка

Нода пишет сразу в две базы — блоков и соцсети. Если её убить посреди записи — `kill -9`, выключение питания, жёсткая перезагрузка сервера, — база может испортиться, и придётся заново разворачивать [снапшот](node-sync.md).

- Останавливайте ноду командой `pocketcoin-cli stop` и ждите: остановка может занять несколько минут.
- В Docker дайте контейнеру время: в `docker-compose.yml` — `stop_grace_period: 10m`, как в примере из README ноды. По умолчанию Docker ждёт 10 секунд и убивает процесс.
- В systemd задайте `TimeoutStopSec=600`: по умолчанию systemd ждёт полторы минуты.

## Автозапуск

Нода должна подниматься сама после перезагрузки сервера. В Docker за это отвечает `restart: on-failure` или `unless-stopped`. Без Docker — служба systemd, например `/etc/systemd/system/pocketcoind.service`:

```
[Unit]
Description=Pocketnet Core
After=network-online.target
Wants=network-online.target

[Service]
User=pocketcoin
ExecStart=/usr/local/bin/pocketcoind -datadir=/home/pocketcoin/.pocketcoin
Restart=on-failure
TimeoutStopSec=600
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

Путь к `pocketcoind` проверьте командой `which pocketcoind`. Затем `sudo systemctl enable --now pocketcoind`. Пример службы с дополнительной защитой есть в репозитории ноды: [contrib/init/pocketcoind.service](https://github.com/pocketnetteam/pocketnet.core/blob/master/contrib/init/pocketcoind.service).

## Резервные копии

- **Кошелёк** — после создания, после шифрования и после импорта ключей: `pocketcoin-cli backupwallet <файл>`. Сам файл `wallet.dat` копируйте только при остановленной ноде. Копию — не на тот же сервер.
- **Настройки** — `pocketcoin.conf` и, если есть, `docker-compose.yml` и служба systemd.
- **Сам блокчейн** копировать незачем: его всегда можно взять со снапшота или из сети.

## Наблюдение

Нода, которая тихо упала или застряла, неделями не приносит наград, и узнаёте вы об этом последним. Проверяйте хотя бы раз в день — лучше скриптом по расписанию:

- **Высота.** `pocketcoin-cli getblockcount` должна совпадать с высотой в [блокчейн-обозревателе](explorer.md) или отставать на один-два блока.
- **Стейкинг.** `pocketcoin-cli getstakinginfo` — `staking: true`.
- **Соседи.** `pocketcoin-cli getconnectioncount` — больше нуля, лучше десяток и больше.
- **Диск.** `df -h` — блокчейн растёт, и место кончается незаметно.
- **Журнал.** `debug.log` в папке данных: при неполадке ответ обычно там.

Простой способ — скрипт в cron, который сравнивает высоту своей ноды с высотой сети и присылает уведомление, если разница больше десятка блоков. Высоту сети отдаёт, например, прокси Bastyon:

```
curl -s -X POST https://1.pocketnet.app:8899/rpc/getnodeinfo -H 'Content-Type: application/json' -d '{"method":"getnodeinfo","parameters":[]}'
```

Высота — в поле `data.lastblock.height`. Если прокси недоступен из вашей сети, спросите другую публичную ноду, см. [Публичная нода для Bastyon](node-public.md#проверка-снаружи).

## Время на сервере

У блоков и транзакций есть время, и ноды отвергают блоки из будущего. Часы сервера должны быть точными: проверьте `timedatectl` — строка `System clock synchronized: yes`. Если нет — включите синхронизацию (`systemd-timesyncd` или `chrony`).

## Журнал

`debug.log` растёт постоянно. При каждом запуске нода сама обрезает его до последних 10 МБ, если не включён подробный журнал (`debug=…`). Если нода работает месяцами без перезапуска, следите за размером файла или настройте logrotate: после ротации пошлите ноде сигнал `SIGHUP`, и она откроет новый файл журнала.

## Безопасность

- Порт 37071 закрыт снаружи, вход на сервер — по SSH-ключу, а не паролю.
- Нода работает от отдельного пользователя, не от root.
- Система обновляется, ненужные службы выключены.
- В кошельке ноды — столько, сколько нужно для стейкинга. Остальное держите там, где ключ не на сервере.
