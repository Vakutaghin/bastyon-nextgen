# Публичная нода для Bastyon

Как сделать, чтобы ваша нода отвечала пользователям Bastyon: какие порты открыть, как её находят прокси и как проверить, что всё работает.

## Как прокси находят ноды

Приложения Bastyon ходят не к нодам, а к прокси-серверам сети. Прокси знают несколько нод из своего кода, а дальше каждые 30 секунд спрашивают у знакомых нод, с кем те соединены, и пробуют каждого нового соседа:

- публичный API — на порту 38081, а прокси, которые требуют шифрования, — на 38881;
- WebSocket для событий — на порту 8087, с шифрованием — на 8887.

Нода, которая ответила и знает свежий блок, попадает в список. Дальше прокси раздают запросы пользователей по самым быстрым и наименее загруженным нодам. Ноду, которая отстаёт от сети больше чем на 20 блоков или ушла на другую ветку, прокси не используют. Старые версии ноды прокси со временем вычёркивают совсем.

Отсюда условия:

- **Постоянный публичный IP-адрес** или хотя бы проброс портов на домашнем роутере. Адрес может меняться — прокси найдут ноду заново, но на это уйдёт время.
- **Открытые порты 37070, 38081 и 8087**, желательно и 38881, 8887. Номера стандартные: на других портах прокси ноду не найдут.
- **Свежая версия** и **синхронизированная** цепочка.
- **Хорошее железо.** Публичная нода отвечает на ленты, поиск и профили, это тяжёлые запросы к базе. См. [Сервер для ноды](node-server.md).

Отдельной награды за публичность нет: это вклад в сеть. Стейкать публичная нода может так же, как любая другая.

## Настройка

В `pocketcoin.conf` публичный API и WebSocket включены по умолчанию (`api=1`). Пример настроек — в статье [Настройка pocketcoin.conf](node-config.md#публичная-нода).

Откройте порты в сетевом экране. Для `ufw` на Ubuntu и Debian:

```
sudo ufw allow 37070/tcp
sudo ufw allow 38081/tcp
sudo ufw allow 38881/tcp
sudo ufw allow 8087/tcp
sudo ufw allow 8887/tcp
```

Если сервер у провайдера с собственным сетевым экраном в панели управления, откройте порты и там.

> [!CAUTION]
> Порт 37071 — управление нодой и кошельком — наружу не открывайте. В Docker публикуйте его только на локальный адрес: `127.0.0.1:37071:37071`, а не `37071:37071`, как в примере из README ноды. Docker обходит правила `ufw`, поэтому опубликованный порт открыт всему интернету, даже если в `ufw` он закрыт.

## Проверка снаружи

С другого компьютера, не с самого сервера, спросите публичный API:

```
curl -X POST http://<ваш IP>:38081/public/ -H 'Content-Type: application/json' -d '{"method":"getnodeinfo","params":[]}'
```

В ответ придёт версия ноды и последний блок (`lastblock`). Высота должна совпадать с высотой в [блокчейн-обозревателе](explorer.md) или отставать на один-два блока. Порт WebSocket проверьте командой `nc -zv <ваш IP> 8087`.

Если ответа нет — проверьте сетевой экран сервера и провайдера, проброс портов на роутере и то, что нода запущена с `api=1`.

То же по TLS: `curl -k -X POST https://<ваш IP>:38881/public/ …` — ключ `-k` нужен, потому что сертификат у ноды свой, самоподписанный.

Найдут ли вашу ноду прокси, зависит от того, с кем она соединена. Обычно на это уходит от нескольких минут до часов. Пока нода не синхронизирована, прокси её не возьмут.

Чтобы ноду находили и новые ноды, её адрес можно попросить добавить в список, зашитый в программу: в [задачах pocketnet.core](https://github.com/pocketnetteam/pocketnet.core/issues) есть шаблон «Request to add an IP address to the source code». Нода для этого должна работать круглосуточно с открытыми 38081 и 8087.

## Нагрузка

- **Запросы к базе.** Ленты, поиск и профили — запросы к SQLite. Если их больше, чем успевает нода, в журнале появляются отказы из-за переполненной очереди, а пользователи получают `sql request timeout`. Помогают быстрый NVMe-диск, больше памяти и потоков: `rpcpublicthreads`, `rpcpublicworkqueue`.
- **Трафик.** Блоки и транзакции другим нодам, ответы прокси — десятки и сотни гигабайт в месяц. Учитывайте лимиты тарифа; ограничить отдачу другим нодам можно параметром `maxuploadtarget`.
- **Процессор.** Раз в 60 блоков нода с публичным API пересчитывает статистику аккаунтов и несколько минут полностью занимает одно ядро. Это нормально, но на двух ядрах в это время всё отвечает медленнее.
- **Соединения.** Публичная нода держит много соединений. Ограничение на число открытых файлов в системе стоит поднять — в Docker это `ulimits: nofile: 65536`, как в примере docker-compose из README ноды.

## Что стоит знать

- **Ваш IP-адрес станет известен.** Его увидят прокси, соседние ноды и любой, кто их спросит. Держите публичную ноду на отдельном сервере, а не на домашнем компьютере с личными данными.
- **Атаки.** Публичный порт могут заваливать запросами. Если это случилось, ограничьте число соединений с одного адреса средствами сетевого экрана или поставьте перед портами nginx.
- **Tor.** С версии 0.22.19 публичный API и WebSocket можно открыть и как скрытый сервис Tor — так нода доступна, даже если её IP закрыт снаружи.
- **Отставание видно сразу.** Нода, которая отстала или упала, просто перестаёт получать запросы, пользователи этого не заметят. Но если она часто пропадает, прокси будут выбирать её реже.

<details>
<summary>Как прокси обращаются к ноде</summary>

Запросы к публичному API — HTTP POST на `http://<адрес>:38081/public/` с телом JSON-RPC: `{"method": "<метод>", "params": [...]}`. Транзакции пользователей прокси отправляют на `http://<адрес>:38081/post/`. Методы управления и кошелька через публичный порт недоступны — только через порт 37071 с паролем.

Через WebSocket `ws://<адрес>:8087/ws` прокси подписываются на новые блоки и события по адресам пользователей.

</details>
